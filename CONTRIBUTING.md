# Contributing to Isogate documentation

Thank you for helping improve the public documentation.

## Before opening a change

1. Read the [complete canonical reference](docs/Isogate-Complete-Documentation.md).
2. Keep statements scoped to documented behavior and clearly label planned or
   historical features.
3. Do not add secrets, credentials, personal data, database exports, logs,
   generated PDFs, implementation source, or private deployment material.
4. Do not make unverified market, audit, decentralization, or safety claims.
5. For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a
   public issue.

## Pull requests

- Explain what documentation changed and why.
- Prefer focused changes with descriptive commit messages.
- Preserve relative links and table formatting.
- Check Markdown links and spelling locally when practical.
- Update the canonical reference first when a supporting page would otherwise
  contradict it.

Contributions are reviewed for accuracy, clarity, privacy, and consistency with
the documented technical-beta status. By participating, you agree to follow
the [Code of Conduct](CODE_OF_CONDUCT.md).
